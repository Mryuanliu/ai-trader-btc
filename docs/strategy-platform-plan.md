## 1. 现状盘点：已经有什么（不要重复造）

平台化的地基其实已经打好了，这是本计划能快速推进的关键：

| 能力 | 现状 | 复用价值 |
|---|---|---|
| **策略契约** | `TradingStrategy` 接口（name/label/paramSchema/normalizeParams/onStart/onTick/onStop/getState） | 直接作为 **SDK 契约**，只需补能力声明与版本 |
| **沙箱边界** | `StrategyExecutor` 是策略唯一交易出口，策略拿不到适配器/密钥 | 已满足"策略不能直接碰交易所" |
| **参数表单** | `paramSchema` 是 JSON Schema，前端动态渲染 | 第三方策略也能自动出配置界面 |
| **篮子（Basket）** | `baskets` 表 + 编号 + 整体盈亏 | 绩效计算的**天然数据单元** |
| **仓位单（Lot）** | `position_lots`，1 开仓↔1 平仓，已实现盈亏落定 | 净值曲线的数据源 |
| **运行意图持久化** | `futures_agent_configs.strategyShouldRun` | 重启自动恢复，可推广到多实例 |
| **行情/日历** | MarketService（WS）+ 财经日历 | 作为平台侧数据服务暴露给策略 |

**结论**：本期不是重写，而是**把已有的内部机制"契约化 + 外显化 + 多例化"**。

## 3. 分阶段实施

每个阶段都可独立交付、独立验收，不阻塞。

### P0 — 契约完善 + 绩效采集（约 2~3 天）

**交付物 1：`StrategyManifest` 能力声明**

给 `TradingStrategy` 补上"平台需要知道的元信息"：

```ts
export interface StrategyManifest {
  /** 语义化版本，用于兼容性与升级提示 */
  version: string;
  /** 作者/来源（内部 / 第三方名） */
  author: string;
  /** 能力声明：平台据此决定是否提供对应数据、是否允许在某些模式下运行 */
  capabilities: {
    /** 需要的行情周期（平台只推送声明过的周期） */
    timeframes: Timeframe[];
    /** 需要逐笔报价还是 K 线即可 */
    needsTicker: boolean;
    /** 支持的市场（当前只有 futures） */
    markets: MarketType[];
    /** 是否会自动平仓（用于提示用户"策略会自己了结"） */
    autoExit: boolean;
    /** 最大建议层数/敞口（仅展示用，平台不做风控） */
    suggestedMaxLayers?: number;
  };
  /** 风险提示文案，上架展示必读 */
  riskNotes: string[];
}
```

**交付物 2：绩效采集（PerformanceService）**

数据源：**篮子（Basket）** —— 它已经把"一轮建仓→了结"聚合好了，且有 `realizedPnl / fundingFee / closedAt`。

按策略名 + 时间窗口聚合，产出净值曲线与指标（详见 §6）。

新增表 `strategy_performance`（按策略×日期的快照，避免每次实时算全量）：

| 字段 | 说明 |
|---|---|
| `strategyName` / `symbol` | 维度 |
| `date` | 日期（日粒度快照） |
| `closedBaskets` | 当日了结篮子数 |
| `realizedPnl` / `fundingFee` / `feeTotal` | 当日累计 |
| `equityCurve` (jsonb) | 当日净值序列，用于画曲线 |
| `peakEquity` / `maxDrawdown` | 回撤计算中间量 |

**验收**：
- 马丁网格跑若干轮后，能在接口查到它的累计收益/胜率/最大回撤
- 指标与篮子明细手工核对一致（口径：已实现盈亏含双边手续费 + 资金费）

### P1 — 策略包 + 动态上下架（约 3~4 天）

**交付物：`StrategyHub` —— 目录即注册**

```
apps/server/strategies/
  martingale-grid/
    manifest.json     ← 元数据（name/label/version/paramSchema/defaultParams/capabilities）
    index.js          ← 实现 TradingStrategy（编译产物或 JS 源码）
```

- 启动时扫描目录 → 读 `manifest.json` → 动态 `import()` 加载实现 → 注册到 Hub
- **下架**：`manifest.json` 里 `enabled: false` 或移出目录 → 若该策略正在运行，先停止实例再卸载
- 提供 `POST /api/strategies/reload` 热重载（不改主代码即可上新策略）

**这一层刻意不做**：策略代码存数据库、在线编辑、热更新到运行中的实例（涉及状态迁移，风险高）。

**验收**：
- 新增一个示例策略（如 `trend-following`）放入目录 → 重启（或 reload）后**策略市场页出现该卡片**、可配置参数、可启动
- 把某策略标为下架 → 卡片消失；若正在运行则先停止并提示

---

### P2 — 多实例运行 + 篮子归属（约 4~5 天）★ 最大改动

这是"多个策略真正互不干扰"的前提，也是之前评估过的「多篮子并行」方案 B。

**改动点**：

1. `StrategyRunner` 从单实例改为**实例表**：`Map<instanceId, RunningInstance>`
   - `instanceId = ${strategyName}:${symbol}`（同策略不同币种 / 不同策略同币种都能并存）
2. `position_lots` 加 **`strategyInstanceId`** 列（迁移）
   - 开仓时写入；`buildContext` 按 instanceId 过滤 → **每个实例只看到自己的篮子**
3. `baskets` 加 `strategyInstanceId`
4. 运行意图持久化改为**多实例**：新增表 `strategy_instances`（instanceId/name/params/shouldRun/startedAt）

**为什么必须有这步**：否则两个策略会互相把对方的仓算进篮子，并互相平仓（这是致命的）。

**验收**：
- 同时启动两个策略实例（不同币种），各自独立挂单/加层/平仓，互不干扰
- 停止其中一个，另一个不受影响
- 重启后两个实例都自动恢复

## 6. 绩效指标体系（行业共识）

| 类别 | 指标 | 计算口径 |
|---|---|---|
| 收益 | 累计收益 | Σ 篮子 `realizedPnl + fundingFee` |
| 收益 | 年化收益 | 累计收益 / 天数 × 365 |
| 风险 | **最大回撤** | 净值曲线从峰值到谷底的最大跌幅 |
| 风险 | 波动率 | 日收益标准差 × √365 |
| 风险调整 | **夏普比率** | (年化收益 − 无风险利率) / 年化波动率 |
| 风险调整 | 卡玛比率 | 年化收益 / 最大回撤 |
| 交易 | 胜率 | 盈利篮子数 / 了结篮子总数 |
| 交易 | 盈亏比 | 平均盈利篮子 / 平均亏损篮子 |

**排行榜主排序建议用夏普**（风险调整后收益，防止"高收益高风险"刷榜），
并强制展示最大回撤——避免用户只看收益。

**注意口径**：必须是**已实现**（篮子 CLOSED）口径，不能把浮盈算进收益，否则排名会被未平仓位污染。

## 7. 关键设计决策与权衡

**D1：绩效单元用「篮子」还是「单笔订单」？**
→ **篮子**。马丁加层时中间层必然浮亏，单笔盈亏没有意义；篮子才是一轮完整周期。
（这也是当初引入篮子的原因。）

**D2：多实例 vs 单实例多币种？**
→ **多实例**。单实例方案只能按币种隔离，同币种跑不了第二个策略；
多实例（instanceId）一次做对，后续扩展成本低。代价是要改 Lot/Basket 归属字段。

**D3：第三方策略代码如何运行？**
| 方案 | 安全性 | 成本 |
|---|---|---|
| A. 只接受审核过的内部策略（目录加载） | 高（人工审核） | 低 |
| B. 外部提交 + `vm` 沙箱 | 中（Node vm 可被攻破） | 中 |
| C. 外部提交 + 独立进程/WASM/容器 | 高 | 高 |

→ **本期走 A**（需求已明确"先跑通闭环"）；若未来开放外部提交，直接上 C，不要停在 B。

**D4：平台是否做风控？**
→ **不做**（已确立的定位：只提供绑定/下单/监控，策略自负风险）。
但**必须在上架页展示 `riskNotes`**，把风险讲清楚——这是"告知"而非"拦截"。

## 8. 风险清单

| 风险 | 影响 | 缓解 |
|---|---|---|
| P2 改 Lot 归属时历史数据 `strategyInstanceId` 为空 | 老仓位归属不明 | 迁移时按 symbol 回填到"legacy 实例"，并在 UI 标注 |
| 多实例同时下单打满保证金 | 交易所拒单 | 每个实例独立 `availableMargin` 检查；平台不做风控但需暴露余额 |
| 策略 `onTick` 抛异常拖垮调度 | 其他实例受影响 | 每实例 try/catch 隔离 + 连续失败自动停止该实例 |
| 绩效指标口径错误导致排名失真 | 决策误导 | P0 阶段与篮子明细逐笔核对，写单测 |
| 热重载时策略正在运行 | 状态丢失 | 重载前先停止实例，重载后按持久化意图恢复 |
